# 服务器无硬件数字人测试台

数字人测试台随 `Dockerfile-web` 构建进管理端镜像，浏览器就是一台虚拟小智设备。它不要求 ESP32，也不要求服务器具有麦克风或声卡。

## 入口与能力

部署最新版管理端镜像后访问：

```text
https://你的智控台域名/digital-human/
```

测试台会自动把 OTA 地址设为当前站点的 `/xiaozhi/ota/`，再使用 OTA 返回的 WebSocket 地址连接正式主服务。可以测试：

- 键盘文字输入；
- 浏览器麦克风录音、ASR、LLM 与 TTS 全链路；
- 摄像头与视觉接口；
- 虚拟设备绑定、智能体切换、角色包、女儿配置和记忆。

公网远程使用麦克风或摄像头时必须通过 HTTPS 打开页面；普通 HTTP 页面通常没有浏览器媒体设备权限。文字输入不依赖麦克风。

## 第一次使用

1. 打开 `/digital-human/`，点击底部“拨号”。
2. 页面会为当前浏览器生成并保存一组虚拟设备 MAC 与客户端 ID。
3. 如果出现设备验证码，到智控台的设备管理中按提示绑定这台虚拟设备。
4. 把虚拟设备分配给要测试的智能体，再次拨号并发送文字或录音。

同一浏览器配置会保存在站点的 `localStorage`。需要第二台独立虚拟设备时，可使用另一个浏览器配置文件或无痕窗口。清除该站点数据会生成新的虚拟 MAC，原绑定不会自动迁移。

## 唤醒词边界

服务器版测试台默认关闭“本地唤醒词”。这里的本地唤醒词桥是为 `python start.py` 在用户电脑上运行时设计的，不能读取远端浏览器的物理麦克风。服务器版仍可用拨号按钮和录音按钮完成真实语音链路测试。

## 部署与验证

从仓库根目录构建管理端镜像，然后在部署目录替换 `XIAOZHI_WEB_IMAGE` 并重建 `xiaozhi-esp32-server-web`。部署后可在服务器本机检查：

```bash
curl -fsS http://127.0.0.1:8002/digital-human/ | grep '小智无硬件测试台'
curl -fsSI http://127.0.0.1:8002/digital-human/js/app.js
```

测试页本身是静态入口，不等于访问控制。公网部署时应继续依赖设备绑定和角色包访问策略；若只允许站长访问，应在外层反向代理或 Cloudflare Access 对 `/digital-human/` 增加登录、账号或 IP 白名单。
